## Closeout

- root_cause: ark-resolver built with four tools and two Python versions (cargo/nextest, maturin, uv, a musl/Alpine Dockerfile; 3.13 in CI, 3.12 in production), sequenced to move to Bazel only after an Axum rewrite that is no longer happening. The PyO3/Sanic hybrid is the long-term service, so its own build had to be unified.
- investigation: Three risks decided the shape. (1) PyO3 without extension-module links libpython dynamically. On macOS that crashed under uv's statically linked interpreter (second libpython, segfault in `ModuleDef::init_multi_phase`), which moved `just run` to `bazel run` while keeping the `.so` copy for pyright. In the linux image the same NEEDED entry resolves through the interpreter's DT_RPATH, so the planned extension-module fallback was never needed. (2) The container import failed for a different reason: hermetic LLVM links with `--unwindlib=none`, so the cdylib had no unwinder (`undefined symbol: _Unwind_GetDataRelBase`). A linux-only static link of llvm libunwind fixed it, with the `_Unwind_*` symbols LOCAL. (3) An unseeded `Cargo.Bazel.lock` drifted about 15 crates; seeding it from `Cargo.lock` before repinning kept exact parity. Reviews also caught a pushed `latest` tag that today's publish never pushed, a five-way hand-copied in-image interpreter path, and a vacuous image check.
- solution: One bzlmod module mirroring sipi's pins: hermetic LLVM ahead of Rust 1.89.0, CPython 3.12, crate_universe `from_specs`, `pip.parse(uv_lock)`, an own `rust_pyo3_toolchain` for PyO3 0.29, `pyo3_extension` producing `ark_resolver/_rust.so`, one glob-derived `py_test` per test module, and a rules_oci image on digest-pinned distroless `cc-debian13` with an explicit-interpreter entrypoint (52 MB against 382 MB). CI calls only `just` recipes through a shared `ci-setup` action. release-please moved to `simple` on `version.txt`. cargo, maturin, the Dockerfile and friends are deleted. A repo `flake.nix` dev shell supplies bazelisk, just, uv and cargo-audit. Test parity held: 168 Rust and 126 Python tests on both paths.
- prevention: `tests/interpreter_path_test.py` fails when a hand-copied interpreter path drifts from the `oci_image` entrypoint. `just image-check` asserts the loaded image's real entrypoint, imports, absence of pip/wheel, TLS roots, tzdata and uid 65532. `just image-tag-check` in CI proves the stamped push tag equals `just docker-image-tag` before a merge exercises the push. The py_test glob stops new test modules from silently never running. `current_config=fail` makes wheel platform mismatches build errors. Follow-ups: split `//src:core` without pyo3 to enforce ADR-0001 in the build graph; automated updates for `crate.spec` and the base digest (Renovate); a CI build cache.
